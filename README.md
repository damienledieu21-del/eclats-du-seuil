# Éclats du Seuil — simulateur de combat

Simulateur de combat C# du futur MMORPG *Éclats du Seuil*, **indépendant de Unity**, sans réseau ni interface graphique.
Le plan complet est dans [PLAN_SIMULATEUR_V0_1.md](PLAN_SIMULATEUR_V0_1.md).

> Toutes les valeurs de jeu sont **provisoires et non équilibrées**.

## Structure

| Projet | Cible | Rôle |
|---|---|---|
| `src/EdS.Domain` | netstandard2.1, C# 9 | Virgule fixe (`Fixed`), temps (`TickRate`), attributs et statistiques (`Stats`), formule de dégâts, règles et description d'un combat (`Combat`), classes, talents et validateur de builds (`Builds`) — aucune dépendance |
| `src/EdS.Simulation` | netstandard2.1, C# 9 | Moteur de combat déterministe (`Engine` : horloge logique, file d'événements, commandes, garde, parade, ressources, états, assaillant, journal JSON Lines, rejeu, vue et soumission pour un pilote), pilote de mesure (`Pilot`, sous-lot 8.6), RNG (`Pcg32`), tirage critique — dépend du domaine seulement |
| `src/EdS.Data` | netstandard2.1, C# 9 | Modèle de données, catalogue du format, validateur commun, empreinte, scénarios — dépend du domaine seulement |
| `src/EdS.Data.Json` | netstandard2.1, C# 9 | Lecture des fichiers de données (analyseur JSON strict sans dépendance depuis le sous-lot 9.1), chargement et rejeu — partagé par les outils .NET, Unity et le futur serveur |
| `src/EdS.Runtime` | netstandard2.1, C# 9 | Pont temps réel pour un client (Unity) : temps réel → ticks, intentions du joueur → commandes, état à afficher et retours, séance d'entraînement (sous-lot 9.2), éditeur de talents (9.4) |
| `src/EdS.Net` | netstandard2.1, C# 9 | Réseau (lot 10) : protocole à messages strict, transport TCP et réseau simulé, salle de combat autoritaire et client ; détail : [docs/RESEAU.md](docs/RESEAU.md) |
| `src/EdS.Server` | net10.0 | Serveur dédié (sous-lot 10.2) : une salle de combat autoritaire sur le réseau local, journaux rejouables |
| `src/EdS.Tools` | net10.0 | Outils .NET : mesures des builds et rapport (`EdS.Tools.Measures`, sous-lot 8.6) |
| `src/EdS.Cli` | net10.0 | Outil en ligne de commande (`rng`, `validate`, `simulate`, `replay`, `report`) |
| `data/` | JSON | `v0/rules.json` (paramètres d'équilibrage et de progression), `v0/classes/bastion.json` (arbres, talents, compétences), `v0/builds/bastion.json` (builds de référence, sous-lot 8.5), `schemas/` |
| `unity/` | Unity 6.3 LTS, URP | Prototype jouable (sous-lot 9.3) : le cœur est compilé par Unity depuis `src/` (paquet local `com.eclats.core`) ; guide : [docs/UNITY.md](docs/UNITY.md) |
| `scenarios/` | JSON | Scénarios de combat (`mannequin.json`, `entrainement_garde_parade.json`, `entrainement_rupture.json`, `entrainement_alterations.json`, `entrainement_declencheurs.json`) ; `coop/duo_meute.json` : coopération à deux Bastions (lot 10) ; `mesures/` : scénarios de mesure S1 à S5 (sous-lot 8.6) |
| `tests/*` | net10.0 | xUnit + FsCheck (tests de propriétés) ; `EdS.Unity.CompileCheck` (netstandard2.1) compile les scripts du prototype contre des bouchons de l'API Unity |

Les projets `netstandard2.1` (domaine, moteur, données et, depuis le sous-lot 9.1, lecture JSON) sont limités à C# 9 et n'ont aucune dépendance externe : ils sont importables tels quels dans Unity (IL2CPP) et sur un serveur .NET.

## Commandes

```bash
dotnet build -warnaserror      # compilation, avertissements bloquants
dotnet test                    # tous les tests
dotnet test --filter Category=Numeric
dotnet test --filter Category=Formula
dotnet test --filter Category=Data
dotnet test --filter Category=Build
dotnet test --filter Category=Engine
dotnet test --filter Category=Resources   # garde, parade, ressources, états (lot 6)
dotnet test --filter Category=Regression  # non-régression du correctif 6.1 (M01 à M05)
dotnet test --filter Category=Limits      # admission, budgets et capacités (sous-lot 7.1)
dotnet test --filter Category=Status      # altérations : DOT, contrôles, immunités, résistances (sous-lot 7.2)
dotnet test --filter Category=Trigger     # déclencheurs, provenance, cycles, profondeur, report (sous-lot 7.3)
dotnet test --filter Category=Modifier    # modificateurs X1 et X2, règles effectives, plafonds (sous-lot 8.1)
dotnet test --filter Category=Shield      # renforcements et boucliers (sous-lot 8.2)
dotnet test --filter Category=Support     # soutien, provocation, protection, rôle allié (sous-lot 8.3)
dotnet test --filter Category=Bastion     # fiches du Bastion, Contrecoup, ripostes de zone (8.4) ; talents, passifs, builds (8.5)
dotnet test --filter Category=Scenario    # compteurs de mesure, pilote, scénarios S1 à S5, commande report (8.6)
dotnet test --filter Category=Runtime     # pont temps réel, séance d'entraînement, paquet Unity, éditeur de talents (9.2 à 9.4)
dotnet test --filter Category=Network     # protocole, transport TCP et réseau simulé (lot 10)
scripts/test-category.sh -c Release Numeric Formula Data Build Engine Resources Regression Limits Status Trigger Modifier Shield Support Bastion Scenario Runtime Network   # échoue si une catégorie est inconnue, vide, ou absente d'un projet qui la déclare
dotnet run --project src/EdS.Cli -- validate
dotnet run --project src/EdS.Cli -- validate data/v0/classes/bastion.json
dotnet run --project src/EdS.Cli -- validate data/v0/builds/bastion.json
dotnet run --project src/EdS.Cli -- rng --seed 42 --count 6
dotnet run --project src/EdS.Cli -- simulate scenarios/mannequin.json --out combat.jsonl
dotnet run --project src/EdS.Cli -- simulate scenarios/entrainement_garde_parade.json
dotnet run --project src/EdS.Cli -- replay combat.jsonl
dotnet run --project src/EdS.Cli -- report                 # mesures des builds de référence (S1 à S5, trois profils) et objectifs
dotnet run --project src/EdS.Cli -- report --json --logs journaux   # rapport JSON reproductible, journaux rejouables
dotnet run --project src/EdS.Server -- --local      # serveur de coopération à deux joueurs (lot 10), port 7777 (--robot : équipier robot)
dotnet run --project src/EdS.Cli -- reseau           # mesures du jeu en réseau (latence, gigue, coupures), rapport Markdown
python3 -m unittest discover -s scripts -p 'test_ci_provenance.py' -v   # générateur du rapport CI non signé
```

Prérequis : SDK .NET 10 (voir `global.json`) ; Python 3 (bibliothèque standard seulement) pour le rapport CI.

CI (`.github/workflows/ci.yml`, check `build-test`) : jeton GitHub en lecture seule (`contents: read`) ; après toutes les étapes de test, `scripts/make_ci_provenance.py` écrit un **rapport auto-déclaré non signé** (`eds-provenance.json` : SHA de tête de la PR et SHA réellement testé, séparés, blob Git du workflow, run et tentative), déposé comme artefact `eds-ci-provenance` pendant 14 jours. Ce n'est **pas** une attestation indépendante : il ne prouve ni la provenance du runner ni l'intégrité des tests ; la signature par un attesteur indépendant est un chantier ultérieur.

## Décisions validées (revue du plan v0.1)

1. Tick initial de 50 ms ; conversion ms → ticks isolée dans `TickRate` pour pouvoir essayer 20 ms.
2. Parade parfaite provisoire : fenêtre de 150 ms, −90 % des dégâts éligibles, +1 Charge de rempart.
3. Limites de déclencheurs conservées ; toute suppression est journalisée explicitement.
4. Compatibilité Unity/IL2CPP de chaque bibliothèque vérifiée avant intégration dans un projet `netstandard2.1`.
5. Puissance d'équipement prévue dans les statistiques offensives, configurable, jamais codée en dur.
6. Un seul talent majeur par build au niveau 30 (voulu) ; les builds sans talent majeur restent valides.

Arbitrages du lot 2 : base offensive 0 et +2 puissance par Force/Dextérité/Intelligence (D1) ; trois puissances d'équipement ajoutées avant le coefficient (D2) ; armure et résistance magique indépendantes, base 0, constante 1000 chacune (D3) ; bonus additifs par catégorie (compétence, talent, altération) et multipliés entre catégories, jamais négatifs (D4). Détail et exemple chiffré : [docs/FORMULES.md](docs/FORMULES.md).
